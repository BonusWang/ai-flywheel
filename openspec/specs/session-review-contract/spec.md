## Requirements
### Requirement: 审查输入与提示词
P02 提示词 SHALL 包含阶段、准入会话（前 6 个，每段正文取头尾摘录：开头 1450 字符、中间省略标记、结尾 1450 字符，总长不超过 3000 字符）、未处理复盘线索的摘要与既有 Skill 名单，并要求模型只返回 JSON，含审查发现、错题、分歧、重复流程候选四个列表。不值得沉淀的会话 MUST 在审查发现里标记 `worthy` 为假并给出原因。周复盘阶段 MUST 提示模型格外关注跨会话的重复流程、与既有 Skill 重叠的流程，以及反复出现、值得沉淀为 Skill 或规则的问题。

#### Scenario: 提示词带齐审查输入
- **WHEN** 生成 P02 提示词
- **THEN** 提示词包含阶段、会话、未处理复盘线索与既有 Skill，并写明四个列表的 JSON 结构

#### Scenario: 长会话取头尾摘录
- **WHEN** 某段会话正文超过 3000 字符
- **THEN** 提示词里的该段正文是开头与结尾各 1450 字符加中间省略标记，总长不超过 3000 字符；短会话原样传入

### Requirement: 审查输出缓存与格式修复
API 与 CLI 审查执行器 SHALL 按阶段与提示词缓存已解析的输出（API 另含地址、模型与推理强度），命中缓存时 MUST 不重复调用模型或 CLI。缓存 MUST 只在审查结果通过语义校验（是 JSON 对象、含 `findings` 列表、且送审了会话时列表非空）之后写入；未通过校验的回复 MUST NOT 落缓存，也 MUST NOT 被下一次同批调用命中。API 模式下回复非空而不是 JSON 对象时 MUST 只做一次仅修 JSON 语法的重试，重试后仍不是 JSON 对象时不再重试；回复为空时不重试。

#### Scenario: 畸形输出只重试一次
- **WHEN** 模型首次返回的 P02 输出不是合法 JSON，重试返回合法 JSON
- **THEN** 执行器发起一次格式修复重试，修复后的输出进入审查结果的判定

#### Scenario: 第二次调用命中缓存
- **WHEN** 同一提示词第二次调用审查
- **THEN** 不再调用模型，结果与第一次相同

#### Scenario: 不可用的回复不落缓存
- **WHEN** 模型的回复没有 `findings` 列表
- **THEN** 执行器不写缓存文件，同一提示词的第二次调用重新询问模型，失败原因不变

### Requirement: 审查来源写进结果
三个审查执行器 SHALL 在审查结果里写明来源：API 执行器为模型，CLI 执行器为本地 CLI，启发式审查器为本地启发式审查器。结果 SHALL 同时给出送审会话数与审查发现条数。

#### Scenario: 三种执行器各报各的来源
- **WHEN** 分别用 API 执行器、CLI 执行器与启发式审查器审查同一批会话
- **THEN** 三份结果的 `review_source` 依次为 `model`、`cli`、`heuristic`，送审会话数与发现条数与各自的结果一致

### Requirement: 审查来源唯一
`api` 与 `cli` 模式下，P02 执行器 MUST 只返回模型或 CLI 输出的审查结果。出现下列任一情况时，执行器 MUST 报告审查不可用并携带诊断，不得返回本地启发式审查：

- 没有回复，或回复（API 模式经一次格式修复后）不是 JSON 对象；
- 回复是 JSON 对象，但没有 `findings` 列表；
- 提示词里有会话，而 `findings` 为空。

提示词里没有会话时，空列表 MUST 视为正常。

#### Scenario: 回复无法解析时报告审查不可用
- **WHEN** `api` 模式下模型的 P02 回复在格式修复后仍不是 JSON 对象
- **THEN** 执行器报告审查不可用，原因为无法解析，不调用本地启发式审查器

#### Scenario: 回复为空
- **WHEN** 模型返回空回复
- **THEN** 执行器报告审查不可用，原因为空回复，不发起格式修复

#### Scenario: 缺少 findings 列表
- **WHEN** 模型回复是 JSON 对象，但没有 `findings` 列表
- **THEN** 执行器报告审查不可用，原因为缺少 `findings` 列表；磁盘上已存在同一批次的坏缓存文件时，诊断给出该缓存文件名

#### Scenario: 送审了会话却没有发现
- **WHEN** 提示词里有 3 个会话，模型返回空的 `findings`
- **THEN** 执行器报告审查不可用，原因为没有发现，不调用本地启发式审查器

#### Scenario: 没有会话时空列表正常
- **WHEN** 提示词里没有会话，模型返回空的 `findings`
- **THEN** 执行器返回 0 条发现的审查，不报告不可用

#### Scenario: 模型的正常审查原样返回
- **WHEN** 模型返回带 `findings` 列表的审查
- **THEN** 执行器返回该审查，来源为模型

#### Scenario: CLI 输出无法解析
- **WHEN** 本地 CLI 的 P02 输出不是 JSON 对象
- **THEN** 执行器报告审查不可用，不调用本地启发式审查器

### Requirement: 审查不可用的诊断
执行器报告审查不可用时 MUST 给出诊断：来源、原因码、送审会话数、回复字符数（有回复时）、是否做过格式修复、缓存文件名与是否命中缓存。缓存文件名 MUST 只在磁盘上确实存在该缓存文件时给出——不可用的回复不落缓存，只有读到了已存在的坏缓存文件时才有文件名可指。回复不是 JSON 对象时，诊断 MUST 说明原因：回复里没有 JSON、JSON 对象没有闭合，或解码器对最外层花括号的报错与出错位置；做过格式修复时，修复后的回复同样处理。格式修复的调用没有完成（例如超时）时，诊断 MUST 记下异常类型，不得记成已做过格式修复；MUST NOT 记下异常的原文。诊断 MUST NOT 包含回复正文。

审查诊断 SHALL 另带本次模型调用的留痕：尝试次数、耗时毫秒、实际服务的模型与 token 用量。网关未给出用量、或调用被替换为桩时，留痕 MUST 记为缺省，MUST NOT 因此报错。

#### Scenario: 诊断不含回复正文
- **WHEN** 模型回复一段无法解析的文本，文本里带有不应外传的内容
- **THEN** 诊断给出原因码、回复字符数与是否做过格式修复，不含回复的任何片段

#### Scenario: 无法解析的回复带上解码器的报错
- **WHEN** 模型回复的 JSON 在第二个发现处被截断
- **THEN** 诊断记下解码器的报错与出错位置，失败信息据此说明回复像是被截断

#### Scenario: 审查诊断带调用留痕
- **WHEN** 一次模型审查完成
- **THEN** 审查诊断带尝试次数、耗时、实际服务的模型与 token 用量，且不含回复正文

#### Scenario: 网关不给用量时留痕缺省
- **WHEN** 回复里没有用量字段
- **THEN** 审查诊断的 token 记为缺省，审查照常完成
