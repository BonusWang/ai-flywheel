## Context

挂载 Schema 治理的 Wiki 后，P03 产出的通用知识文档由落点适配层（`WikiGate.normalize_planned_document`）改写成 T5 经验卡。「归哪个项目」目前由证据判定：来源会话的工作区路径优先，其次是草稿前 600 字符里的项目标识；没有证据就不写。

真实运行（2026-11-24 #1）暴露的问题是判定不精确。复盘证据：

| 证据 | 方式 | 结果 |
|---|---|---|
| 4 篇文档的来源工作区 | 读运行库 | 都不在任何 Wiki 项目目录下，工作区证据全部为空 |
| 被误归的那篇 | 用现有词面规则复算 | 前 600 字符同时命中两个项目，取了被顺带提及的那个 |
| 被移出的那篇 | 同上 | 全文没有任何项目标识 |
| 模型自己为同批写的 2 篇草稿 | 读 P03 缓存输出 | 全文没有任何项目标识，也不带来源会话键 |
| 挂载合同声明的页面类型 | 读 `.wiki-schema.md` | 24 种；落点适配器只会映射 T5 |
| 含 `实战笔记/` 的项目目录 | 读挂载 Wiki | 4 个，都带索引页（`project_id`、别名、描述） |

## Goals / Non-Goals

**Goals:**
- 「关于某项目」与「顺带提到某项目」由读过会话内容的模型区分，系统只做确定性校验。
- 草稿里没有项目标识的真归属笔记不再漏判。
- 页面类型与项目候选来自挂载 Wiki 的合同与目录，不硬编码。
- 每个路由决定都留痕：谁声明的、证据是否支持、为什么没写。

**Non-Goals:**
- 不做 T5b 轻记卡或其他页面类型的落点映射。
- 不把跨项目 / 治理类笔记写进 topics 或 synthesis。
- 不改写前 / 写后门禁规则，不改 T5 正文保真映射。
- 不修 P03 静默兜底与空壳 Skill（fix-p03-silent-plan-fallback）。

## Decisions

### 1. 归属与页面类型由 P03 模型声明

备选一是保留词面判定并继续加规则。把窗口扩到全文能救回被移出的那篇，但救不了被误归的那篇：它同时命中两个项目，词面没有依据二选一。备选二是单独加一次模型调用做路由：多一次调用、多一个超时点，而 P03 本来就在写这篇文档。选择让 P03 在计划里顺带声明，每篇多输出约 100 字符。

### 2. 证据降为校验，冲突的定义收窄

证据不再选择项目，只回答"声明是否被证据反驳"。校验对每个候选项目分别算两组命中：

- 工作区命中：来源会话工作区路径的某一段等于候选的目录名或 `project_id`，或该段包含候选的项目标识；
- 内容命中：候选的项目标识出现在草稿全文（标题、摘要、正文）中。

冲突只有两种：工作区命中非空且不含声明项目；工作区命中为空、内容命中非空且不含声明项目。证据为空不算冲突，这正是草稿没有项目标识的真归属笔记能写进去的原因；命中多个项目且包含声明项目也不算冲突。

备选一是证据只记日志不参与判定：声明错了也直接落盘，`smart` 模式下没人看。备选二是证据命中时仍由证据选项目：草稿顺带提到别的项目时又会把声明盖掉，回到原问题。

### 3. 冲突与无归属都不写，只留痕（维护者定）

| 情形 | 选择 | 备选与否决理由 |
|---|---|---|
| 声明与证据冲突 | 不写，`planned_doc_unrouted` 写明声明、证据命中与冲突类型 | 照声明写入：错归的卡不经人工落盘。挂起等审批：定时批会挂起到维护者处理，`auto` 模式下仍无人审 |
| 声明「无归属」 | 不写，载荷保留模型给出的理由 | 写 topics：新主题页没有活跃反链时 lint 判孤儿，写入回滚、整批失败，需要「主题页加反链」的多页写入。写 synthesis 的对话结晶：需要新的映射器与字段取值口径，后检约束未核实。两者都与合同「跨项目规律先跨语境复测再升格」相悖 |

### 4. 候选集动态发现，用映射器注册表收口

页面类型候选 = 合同 `content_contract.page_types` 中、所属分区在分区合同里可解析、且落点适配器登记了正文映射器的类型。项目候选 = 项目分区下含 `实战笔记/` 的目录，带 `project_id`、别名与描述（取自该目录 `实战笔记/笔记索引.md` 的 frontmatter）。

备选一是开放合同里的全部页面类型：没有映射器的类型必在写前门禁失败，整批运行失败。备选二是沿用硬编码：换一个合同不同的 Wiki 就写错地方。候选为空时如实为空、全部不写，不回退到内置类型；此时提示词直接告知模型不要输出知识文档项，不要求声明。

候选项目的别名与描述取自该项目 `实战笔记/笔记索引.md` 的 frontmatter。那是索引页的别名与说明，不是项目定位语；它够用是因为目录名本身带着项目标识与中文名。枢纽页的描述更贴近「项目是做什么的」，但识别枢纽页要依赖某个 Wiki 特有的命名，没有采用。

实现中否决了一条自己加的规则：「页面类型的分区还必须落在允许写入前缀内」。允许写入前缀是配置而不是合同；按它过滤，配置与合同不符时会从「P04 大声失败」变成「P03 全部不写而运行通过」，把配置错误藏起来。前缀不符仍交给 P04 的写入门禁显式拒绝。

同一类问题还有一处，自审时补上：合同读不出来（`.wiki-schema.md` 缺机器块或无法解析）时，候选集会是空的。如果照「候选集为空」处理，提示词会让模型别输出知识文档，运行静默通过、零写入；而改动前这种情况在 P04 由写入门禁以 `SCHEMA_UNREADABLE` 失败。现在发现候选集时直接抛 `WikiGateError`，运行在 P03 失败并指明缺什么。候选集为空的「全部不写」只留给合同本身确实没有可映射类型或项目的情形，那是合同的一致状态而不是错误。

### 5. 页面类型本次只开放 T5 重卡（维护者定）

备选是同时开放 T5b 轻记卡，另增一套 20 行上限的三段式映射。没有轻记卡需求的真实证据，P03 现在产出的草稿也是事件复盘形态。映射器按页面类型注册，之后要加只需登记一个映射器。

### 6. 声明只做标识精确匹配

声明的项目只认目录名、`project_id` 或别名的精确匹配（忽略大小写），命中多个候选视为无效。备选是模糊匹配或词面匹配，那会把「顺带提到」的问题带回来。声明不在候选集内时按无归属处理，不纠正到最接近的候选。

### 7. 无声明的计划：只有零配置演练执行器走证据判定

零配置演练执行器没有模型可声明，沿用现有证据判定，留痕时标 `route_source=evidence`。API / CLI 执行器的计划缺声明按「声明缺失」不写。备选是 API 计划缺声明也走词面判定，那正是上一轮事故的上游形态：配置要的是模型计划，落盘的却是别的来源。

### 8. 声明载体与已合规草稿

声明放在 `PlannedWrite.wiki_route`，执行器原样带到编排器，校验前不改写。备选是写进草稿 frontmatter（会被归一化覆盖）或藏在路径里（脆）。草稿在其目标路径上已通过写前校验时路径为准：页面类型必须属于可路由类型，声明项目必须与路径所示项目一致，否则不写。

### 9. 留痕面

路由结论进 P03 节点载荷（已路由与未路由两张清单）、审计事件（`planned_doc_routed`、`planned_doc_unrouted`）与 P03 摘要（未写入数量与原因分布）。下次再出现「这张卡为什么在这个项目里」，读审计即可，不必再回放运行库。

### 10. 验证分三级

- test：合成 Schema 的 pytest，覆盖候选集发现、声明校验的每条分支、无声明路径与端到端留痕。
- real：沙箱回放（真实编排器 + 真实挂载 Schema + 真实 D2 后检；知识根、数据目录、证据目录全部重定向到副本，飞书 / Webhook / Git 收口 / Skill 写入硬关闭）。先用桩执行器跑通写入链路，再用日常配置的模型网关单独跑一次 P03，验证模型能否给出合法声明及耗时。真实模型调用经维护者授权（2026-11-24）。
- 真实知识库上的运行需要维护者另行授权，本变更不自行触发。

### 11. 与 fix-p03-silent-plan-fallback 的先后

两个变更都改 `runners.py`、`models.py` 与 P03 编排段。本变更的实施分两步：门禁侧（候选集发现与路由校验）不依赖对方，可以先落；提示词、`PlannedWrite` 与编排器接入等对方修复落到工作区并完成验证之后再改，避免两个会话同时写同一批文件。

本变更 MODIFIED 五条需求，它们的现役文本都来自两个前置变更：`通用计划文档归一化为 T5 经验卡`、`无法归属项目的知识文档处理` 来自 fix-p04；`P03 路由与写入计划`、`计划输入与提示词`、`输出契约列明必填字段` 来自 fix-p03。增量里写的是合并了它们的文本之后的版本，所以归档顺序固定为：fix-p04-practice-card-adaptation → fix-p03-silent-plan-fallback → 本变更。顺序反了，后归档的增量会用旧文本覆盖前面的修改。

两个前置变更已于 2026-11-24 15:51 按此顺序归档。归档后逐条比对：本变更的增量相对主规格少掉的行全是有意替换的（证据判定改为声明校验）或并入同段的句子，没有误删继承来的内容。

## Risks / Trade-offs

- [模型声明错但与证据不矛盾] → 例如把跨项目审计声明成被提及的那个项目，证据拦不住。靠审批门与留痕事后发现；真实模型调用的结果记入 evidence.md。
- [提示词变长] → 路由部分约 2 千字符（实测录制批次的提示词共约 1.16 万字符）；真实模型单次调用 178 秒，上一次真实运行 147 秒，阈值 240 秒。候选只给标识与一句说明；耗时增量无法单独归因于路由，见 evidence.md。
- [Wiki 项目名进入提示词] → 会随请求发给模型网关。与日常运行已发送的会话内容属同一类别。
- [演练执行器的计划仍靠词面判定] → 已知不精确，但只在零配置演练模式下生效，留痕可与声明路径区分。
- [未写入的知识文档仍占用单批数量名额] → 既有行为，本变更不改；未写入数量现在在 P03 摘要里可见。
- [真实知识库上的完整运行尚未执行] → 对应任务保持未勾选，变更在其完成前不归档。
