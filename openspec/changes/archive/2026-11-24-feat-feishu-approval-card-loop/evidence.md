## 4. 监听器与服务停止（real，任务 7.3）

| 断言 | 结果 |
|---|---|
| 另起一个消费者时被拒 | 退出码 2，文案 `another consumer (pid …) is already running`，与分类器的「被占用」标记一致 |
| 冲突期间 serve 的监听不受影响 | 仍就绪 |
| 门户页面开着（SSE 长连接在途）时停止服务 | 10.8 秒自行退出，退出码 0（关闭宽限 10 秒生效） |
| 退出 2 秒后没有残留的消费者进程 | 通过；只剩事件总线守护进程 |
| 事件总线守护进程自行退出 | 约 29 秒后全部 lark-cli 进程消失，状态 `not_running` |

执行到一半的批准请求不受 Ctrl+C 影响：已由变更 A 的沙箱验证覆盖，必要时强制结束。

## 5. 真实验证暴露并修复的缺陷（先失败后修复）

| 缺陷 | 影响 | 修复 |
|---|---|---|
| 回写线程把刚送达的待决卡当成「状态落后」，30 秒内覆盖成无按钮的「已选择」卡 | 审批卡上的按钮在送达后十几秒就消失，维护者根本无法点击（此前多轮「点击没到」的真实原因） | 送达即记录已同步；待决卡只在监听不可用 / 恢复时改写 |
| 旧行迁移每次启动都重跑 | 已送达的交互卡被改记为文本行，重启后不再回写状态 | 迁移只跑一次 |
| `flywheel serve` 自建运行时未传 `serve` 角色 | 交互卡被当作非 serve 进程拒发 | serve 路径显式传角色 |
| 交互模式未开时也启动点击监听 | 空占该应用唯一的卡片点击订阅，别处无法监听 | 监听只在交互模式开启时运行，运行中关闭数秒内停掉 |
| 锁忙提示把待决卡改写成无按钮，并给出误导性的锁到期时间 | 提示「稍后重试」却无法再点 | 提示改为操作区上方的一次性说明，按钮保留，不给时间 |
| 清洗顺序：全角化先于脱敏 | `<private>` 变全角后脱敏失配，敏感片段原样外发 | 先剥离与掩码，再全角化 |
| 文本兜底未清洗 | 降级后的文本通知带出原始标题 | 同一套清洗 |
| 包装脚本解析正则命中 node.exe 探测行 | 解析到错误的可执行文件 | 只认 node_modules 下的入口 |
| `auth status --format json` 不是合法参数 | bot 身份永远判为未就绪 | 改用 `--json` |

另：卡面排版按维护者反馈重做（每条写入独立成块、主操作蓝底撑满、取消为次级按钮、空字段不显示）。

真实运行还暴露了两处**尚未修复**的缺陷：启动后的首轮补投抢跑；降级为文本但实际已送达的卡片不回写（维护者点了取消，运行已取消，卡片上的按钮还在）。连同独立评审发现的其余缺口，见 `verify-report.md`。
