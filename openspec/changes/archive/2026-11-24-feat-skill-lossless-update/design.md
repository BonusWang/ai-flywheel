# Design：Skill 更新不丢内容

> 2026-11-25。证据分级：real = 真实数据（只读运行库、缓存输出与技能目录的统计），test = 自动测试；
> static = 静态判断（读代码）；unknown = 未验证。本页已脱敏：现有 Skill 用甲、乙、丙、丁代称，不含路径、会话键、真实名称、网关与模型名。

## 1. 决策：更新 = 在文件末尾追加小节

| 方案 | 不丢内容的保证 | P03 耗时 | 审批改动量 | 判断 |
|---|---|---|---|---|
| A 现有全文进提示词，模型输出完整文件 | 弱：靠模型遵从；加确定性校验后又退化成 B | 可见输出多 5–6.4 千 tokens，多 20–60 秒，叠在最慢一批上贴着 240 秒超时 | 中 | 不选 |
| B 更新改为追加小节 | 强：由构造保证——现有字节是新文件的���缀，写入器断言这一点 | 不增（模型现在给更新项写的也是约 0.4 千字符） | 小 | **选** |
| C 保持整文件替换，审批并排显示新旧 | 无：只是让丢失可见 | 不变 | 大 | 只取其界面部分 |

**决定**：B 加 C 的界面部分。理由是「保留原有内容」不能是模型的任务；一旦要求模型复述全文，超时余量先耗尽（最慢一批只剩约 60 秒），而确定性的校验最终又不允许原地修订，B 已经是 A 的可行形态。

**代价**：更新只增不改——不能原地修订、不能删除过时步骤。需要时人工修订，或另立带新旧对照的修订动作。

## 2. 决策：追加内容先归一化，再由写入器落盘

模型仍写整份文件是常态（录得的 5 项全是完整 `SKILL.md`）。归一化做三件事：

1. 剥掉 YAML frontmatter——更新不改 frontmatter，`description` 也就不会被模型换掉；
2. 剥掉一级标题——追加的是小节，不是又一份文件；
3. 保证正文以二级标题开头，没有就包进 `## {标题}（{当天} 补充）`。

**归一化必须幂等**：P03 归一化过一次，写入器再归一化一次（防止绕过 P03 的直接调用）。日期后缀只带一次，因此第二次归一化看不到变化。

**归一化在哪一层做**：P03 与写入器都做。P03 做，是为了让审批人看到的预览就是将要追加的内容；写入器做，是为了任何直接调用写入器的路径也有同样的保证。

## 3. 决策：不丢内容由构造保证，而不是由校验保证

写入器构造新文件时，现有字节是前缀：

```
new_bytes = existing_bytes (+ 换行补齐) + 空行 + 追加小节 + 末尾换行
```

随后断言 `new_bytes.startswith(existing_bytes)`，不成立就拒绝写入并报错。断言之外还有回读 SHA-256 比对。

**备选**：写入后逐行比对旧内容是否还在。那需要先解析旧文件、定义「还在」的含义（顺序？内容？），而且只能发现丢失、不能防止丢失。构造性前缀不需要任何定义。

**行尾**：现有文件 20/50 用 CRLF、30/50 用 LF。追加时沿用原文件的行尾，原有字节一个不动。

## 4. 决策：三道护栏，都不靠模型

| 护栏 | 位置 | 处置 |
|---|---|---|
| 目标不存在 | P03 归一化 | 丢弃留痕，`UPDATE_TARGET_MISSING` |
| 目标 frontmatter 不合规 | P03 归一化 | 丢弃留痕，`UPDATE_TARGET_INVALID` |
| 追加内容与现有内容完全重复 | P03 归一化 | 丢弃留痕，`UPDATE_NO_NEW_CONTENT` |
| 计划之后目标被删 | 写入器 | 报错，不另起新文件 |

**重复判定**：把追加内容里每一行有内容的行（忽略空行、裸标题标记与裸列表符号）拿去与现有文件逐行比对；标题行按去掉日期后缀后的标题比对，因为归一化会给标题加上日期后缀。全部命中才算重复。

**为什么不放在写入器**：写入器已经晚了——那时审批人已经看过预览、也已经点了同意。丢弃要在审批之前发生。

## 5. 决策：提示词只给现有小节标题，不给全文

模型需要知道的是「已经覆盖了什么」，不是「全文是什么」。给出二级标题清单的代价约 0.2 千 tokens；给出全文的代价是 6.9 千 tokens 输入与不可控的推理增量。

**未知**：小节清单会带来多少推理增量。耗时几乎全部随推理走（可见输出只占输出 tokens 的 6–21%），而推理增量与输入增量没有对照数据。本变更不因此阻塞：输入增量小，且追加语义不改变模型要写的体量。

## 6. 决策：审批卡并排对照

审批人需要回答的问题是「这次追加的东西，和现有内容重复吗」。为此门户显示：现有文件的行数、已有小节清单、可展开的现有全文；新内容标注为「新增小节（追加到文件末尾，原有内容不动）」。

现有全文按需读取（一个只读接口），不复制进运行记录、事件流与回执——现有 Skill 可能上百行，把它复制进每一处留痕会污染这些记录。

**冲突判定不做自动化**：追加的小节可能与现有内容语义冲突（例如重述了适用范围）。提示词要求只写没覆盖的内容，审批卡并排对照，冲突由人判断。

## 7. 风险与未验证项

| 项 | 说明 |
|---|---|
| 模型是否照做「只输出增量小节」 | 未验证。契约已写明提示词，归一化能兜住模型仍写整份文件的情况，但兜住不等于写得好 |
| 追加小节的质量 | `auto` 审批模式下仍无人审。换方案后不再丢内容，但写得对不对仍靠提示词与人工 |
| 现有内容与追加小节的语义冲突 | 不做自动化判定 |
| 原地修订与删除 | 本变更不提供 |
| 现有文件里已有同名小节 | 提示词要求不重复，重复判定只拦「内容全重复」，拦不住「标题相同但内容不同」 |

## 8. 真实验证方式

- **test**：写入器的追加路径（原字节保留、行尾沿用、缺失目标报错、备份与 SHA 回读）、归一化的三种形态与幂等性、P03 的三道护栏与审批理由、只读预览接口。
- **real**：在沙箱技能目录副本上，用真实编排器 + 真实模型输出走一遍更新，确认落盘文件以原有字节开头、追加小节在末尾、门户预览与落盘内容一致。真实技能目录上的更新需维护者授权。
