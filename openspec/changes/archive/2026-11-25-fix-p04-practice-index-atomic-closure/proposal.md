## Why

P04 已能把会话归一化为项目实战重卡或轻记卡，并把卡片原子落盘，但没有同步更新该项目的
`实战笔记/笔记索引.md`。真实回放发现新卡可以显示“写入成功”却无法从项目笔记索引中查到，
形成孤儿卡；现有 D2 后检也只收到卡片路径，无法知道同一次写入还改变了哪个派生登记面。

这不是索引生成器缺失，而是写入事务边界不完整：审批计划只包含主卡，P04 不校验派生路径，
文件写入与项目索引又没有统一的锁、补偿回滚和证据。单纯在写入后追加一行仍会在并发、重试、
后检失败和历史待审批计划重载时产生漏登记、重复或越权写入。

## What Changes

- P03 为每张 `project-practice-note` / `project-practice-lite` 生成精确的项目笔记索引副作用，
  包括目标索引路径、条目预览和当前状态，并随写入计划持久化供门户与消息卡审批。
- P03 把主卡与项目索引都计入单批物理写入路径上限，避免主卡数量不超限但派生登记使写入面膨胀。
- P04 在任何业务副作用前复核已批准的物理路径集合；在目标索引锁内重新读取并生成登记计划，
  只允许执行与审批预览逐项一致的新增。
- 主卡与索引采用补偿式原子提交。任一写入、回读或 D2 后检失败时恢复两处 preimage，并把
  卡片、索引、回滚和重同步结果写入同一份门禁证据。
- 同一索引的锁内重读保证并发卡片不互相覆盖，精确链接去重保证重试和历史计划重复执行不产生重复条目。
- 缺少索引、索引路径变化、历史待审批计划没有副作用记录或实际条目与批准内容不一致时失败关闭，
  不写入主卡，也不产生数据库侧 P04 副作用。

## Capabilities

### New Capabilities

无

### Modified Capabilities

- `knowledge-write-gate`: 项目实战卡与其项目笔记索引的同一事务登记、回滚、去重、并发锁和证据。
- `workflow-orchestration`: P03 审批预览与物理写入预算，以及 P04 的批准范围复核和派生写入回执。

  `adapters/wiki/gate.py`、`adapters/knowledge.py`、`core/pipeline/coordinator.py`。

- 数据：无数据库迁移，无新外部依赖，无 API 路由数量变化。
