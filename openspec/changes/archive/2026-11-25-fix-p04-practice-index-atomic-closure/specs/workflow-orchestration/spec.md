## MODIFIED Requirements

### Requirement: P04 受控写入

P03 SHALL 在写入计划中为项目实战卡携带项目笔记索引副作用预览，并提供主卡与索引去重后的物理写入路径数。
该预览 MUST 随运行记录持久化，控制台和已启用的审批消息通道 MUST 显示索引目标与待新增条目。

P04 MUST 在处理错题、分歧、知识、规则或 Skill 之前复核所有已批准知识写入的物理路径集合，
总数不得超过 `knowledge_sink.max_write_set`。对每张项目实战卡，P04 MUST 在目标索引锁内按最新文件
重新生成登记计划，并与该计划项保存的索引副作用逐项比对目标、动作与条目内容。实际需要新增但审批中
没有对应记录，或目标/条目与批准内容不一致时 MUST 失败关闭，且不得写入主卡。

同一项目索引被多张已批准卡片共用时 SHALL 计为一个物理路径。重复执行和历史运行中出现卡片条目
已存在的状态时 MUST 去重，不新增第二行。

P04 SHALL 把实际项目索引路径加入写入回执、节点载荷、审计可见的产物路径和可选本地 Git 提交范围。
D2 后检、自动 Git 提交与失败回执 MUST 使用同一组已批准的物理路径。

#### Scenario: 审批前可见索引副作用

- **WHEN** P03 生成一张需要新增索引条目的实战卡
- **THEN** 写入计划项含索引目标、动作和精确条目预览，运行重载后这些字段仍存在

#### Scenario: 共享索引只占一个物理路径

- **WHEN** 同一批三张卡片属于同一项目
- **THEN** 三张主卡与一个项目索引共同参与物理路径上限计算

#### Scenario: P04 在锁内重读

- **WHEN** 审批后同一索引已被另一进程追加了其它卡片
- **THEN** P04 重读最新索引，保留其它条目，再追加本次已批准条目

#### Scenario: 历史计划缺少副作用批准

- **WHEN** 持久化的旧计划需要新增索引条目但没有 `side_effect` 记录
- **THEN** P04 失败关闭，不写主卡，要求重新生成计划并审批

#### Scenario: 索引路径或条目漂移

- **WHEN** P04 重新计算的索引目标或条目与已批准内容不同
- **THEN** P04 在任何业务副作用前失败，计划项不被部分执行

#### Scenario: 索引加入 Git 范围

- **WHEN** `auto_git_commit` 为真且本次新增了项目索引条目
- **THEN** 本地提交只包含已批准主卡与项目索引，P04 载荷和审计事件列出相同文件

## ADDED Requirements

### Requirement: 项目索引失败状态可见

P04 SHALL 在项目索引登记失败、D2 阻断、回滚或同步失败时保留结构化状态。运行终态 MUST 使用现有失败契约，
下游节点标记 `SKIPPED`，准入会话回到 `pending`，并释放独占锁。

#### Scenario: 主卡写后索引回读失败

- **WHEN** 项目索引写入后回读内容与计划不一致
- **THEN** P04 恢复两处 preimage，抛出门禁错误，运行 `FAILED`，P05–P07 为 `SKIPPED`
