## Context

挂载 Schema 治理的 Wiki 后，P03 执行器仍按"通用知识文档"契约产出计划（frontmatter 无 `type`、路径直接位于项目分区根），与 Wiki 的 T5 经验卡合同不一致。上一轮在知识落点边界加入确定性归一化（P03 / P04 各调用一次），方向正确：执行器输出不可信，由落点适配器负责转成挂载合同。

本轮排查证据（2026-11-24）：

| 验证 | 方式 | 结果 |
|---|---|---|
| 失败批次的计划文档经当前代码归一化后过写前门禁 | 只读回放，真实挂载 Schema | 4/4 `ok=True` |
| 失败批次的已批准写入跑完整 P04–P07 | 真实编排器 + Wiki 沙箱副本 + 真实 D2 后检 | `PASS`，3 篇写入，validator 0 error |
| 写入卡的项目归属 | 对照来源会话工作区 | 3/4 篇与目标项目无关，靠兜底偏好写入 |
| 写入卡的正文 | 对照原稿 | 「错误示范」为固定话术；真实异常被挤到「关键事项」 |

## Goals / Non-Goals

**Goals:**
- 经验卡只落在有证据支持的项目下；没有证据就不写，并让维护者看得见。
- 写入卡忠实于原稿：不丢要点、不编造错误示范、不把会话编号当描述。
- 无法归属的笔记不再让整批运行失败。

**Non-Goals:**
- 不改造 P03 执行器提示词去直接产出 Wiki 合同文档。
- 不处理同日重名覆盖保护。
- 不改变写前 / 写后门禁的校验规则。

## Decisions

- **项目归属：工作区证据 > 内容证据 > 不写。**
  备选一是保留"兜底偏好"（现状），会把无关会话的知识写进固定项目，属于知识库污染。备选二是无证据时整批失败，会让一批里只要混进一个无关会话就全部零写入。选择"跳过并留痕"，并用可选配置 `practice_fallback_project` 把"要不要兜底、兜到哪"交还给维护者的私有配置，而不是写死在公开代码里。
- **证据的判定收紧到"项目标识"。**
  只认 `project_id`、完整目录名、目录名开头的连续 ASCII 词；ASCII 标识要求字母数字边界；长度小于 3 的片段与通用词（core、web、service 等）不算。旧逻辑把目录名按分隔符切成片段且长度不小于 2 即可匹配，`ai` 这类片段几乎命中所有英文内容。
- **正文按草稿小节映射，不做内容合成。**
  备选是保留"前 3 条进好流程、第 4–6 条进关键事项"的固定切分。它依赖要点顺序，且「错误示范」只能填模板话术。改为按二级标题分桶归位；某类为空就如实写"未记录"。
- **无法归属的判定在归一化入口以返回值表达（`None`），不用异常。**
  这是可预期的业务结果而非错误；P03 / P04 据此跳过并留痕。签名从恒返回二元组改为可返回 `None`，调用点只有编排器两处与一个测试。
- **验证分两级：test 用合成 Schema 的 pytest；real 用沙箱回放。**
  沙箱是知识库副本，知识根、数据目录、证据目录全部重定向，飞书 / Webhook / Git 收口 / Skill 写入硬关闭；真实知识库上的完整运行需要维护者授权后另行执行。

## Risks / Trade-offs

- [收紧证据后，原本"总能写进去"的笔记变为跳过，沉淀量下降] → 跳过项在 P03 摘要、载荷与审计事件中可见；需要兜底时在私有配置里指定 `practice_fallback_project`。
- [工作区路径含项目名但内容与项目无关] → 工作区证据优先是有意的取舍：会话在该项目目录下发生，归属该项目的概率最高；维护者可在审批阶段取消该项。
- [真实知识库上的完整运行尚未执行] → tasks 3.2 保持未勾选，变更在 real 级验证完成前不归档。
